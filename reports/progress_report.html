CANDOR-D4J: multi-agent LLM test generation on real Defects4J bugs

Can a CANDOR-style multi-agent test generator, which works well on single-method benchmarks (HumanEvalJava, LeetCodeJava), detect real bugs in real projects? First results on a 40-bug development set, against EvoSuite.

Headline (28 of 40 development bugs finished)

16 / 28bugs detected by our framework (57%)
12 / 28bugs detected by EvoSuite (43%)
19 / 28detected by at least one (68%): the tools are complementary
8.4LLM calls per bug, free-tier model only

"Detected" uses the standard Defects4J protocol: a generated test passes on the fixed version and fails on the buggy version. The same Defects4J scripts judge both tools. For reference, published numbers on other Defects4J subsets are AdverTest 66.6%, HITS 61.4% and EvoSuite 40.8% (from the AdverTest paper). These use different bugs and models, so they are not directly comparable.

Approach

The approach combines CANDOR's oracle consensus, AdverTest's adversarial mutant loop, and a new project-context stage that CANDOR lacks (its subjects have no dependencies). Tests are generated on the fixed version. The LLM never sees the buggy code, the fix, or the developer's bug-revealing test.

Why bugs were missed

In most of the missed bugs our tests did reach the buggy method (often at 100% coverage), but never produced the specific input, environment or check that exposes the fault.

Engineering issues found and fixed

  • EvoSuite crashed when run in parallel, and when Wi-Fi changed (RMI). It now runs sequentially on loopback, and crashes are retried instead of being recorded.
  • PIT failed on projects that ship JUnit 3 (Cli, Closure). JUnit 4.12 now goes first on the classpath.
  • Focal-method detection now handles field-only fixes, class-header-only fixes and classes added by the fix.
  • Coverage feedback added to the mutant loop. Cli-38 went from missed (0% method coverage) to detected.
  • Coverage of constructor focal methods was mis-measured; it is now computed per line.

Validity

Development set. The 40 bugs (all 17 Defects4J projects) were used to find weaknesses, including reading their fixes. Final claims will be reported on the remaining 158 unseen bugs of the 198-bug main set, with all tools on the same bugs.
  • Like AdverTest and HITS, the method under test is chosen from the Defects4J patch. The LLM sees only the fixed code.
  • A free, small model (flash-lite) is used throughout; published systems use DeepSeek-V3 or GPT-4o.
  • Data contamination: Defects4J is public. A newer-bug check (GrowingBugs) is planned.
